2 ЗАВДАННЯ
     На цій лабораторній роботі потрібно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.



3 ОПИС ВИКОНАНОЇ РОБОТИ

	3.1 Опис роботи
     У рамках виконання завдання було розроблено front-end частину програмної системи CareLink - платформи автоматизованого догляду, соціальної підтримки та цифрової освіти літніх людей. Розроблена частина системи забезпечує роботу клієнтів у веб-режимі та підтримує повноцінне адміністрування системи через окремий інтерфейс.

     Технологічну основу застосунку складають React 18, бібліотека маршрутизації React Router v6, HTTP-клієнт Axios для взаємодії з REST API, а також бібліотека i18next для реалізації інтернаціоналізації та локалізації.
     
     Розроблений інтерфейс поділено на три функціональні блоки: публічний розділ, доступний без авторизації; розділ звичайного користувача та розділ адміністратора. Доступ до захищених маршрутів контролюється компонентом Auth Guard, який перевіряє наявність JWT-токена та роль користувача.
     
     Реалізовано вісім сторінок для авторизованих користувачів із ролями «літній користувач», «родич», «медичний працівник» та «адмінінстратор».
     
     Сторінки здоров'я та IoT-даних, моніторингу пристроїв, когнітивних вправ не були реалізовані в рамках поточної роботи. Причиною є технічна залежність цих модулів від зовнішніх інтеграцій, які виходять за межі завдання з розробки front-end частини.
     
     Було розроблено сторінки адміністративного інтерфейсу, доступних виключно для користувачів із роллю «administrator», а саме: панель адміністратора, управління користувачами, системні логи, управління вправами, резервне копіювання та експорт.
     
     На всіх сторінках системи реалізовано підтримку двох мов української та англійської. Переключення мови відбувається через перемикач у хедері без перезавантаження сторінки; поточний вибір мови зберігається в localStorage за ключем «carelink_lang» і відновлюється при наступному відкритті застосунку.
     
     Дати та час у всьому інтерфейсі відображаються у форматі, що відповідає обраній локалі: `дд.мм.рррр` для української мови та `мм/дд/рррр` для англійської. Сортування текстових значень у таблицях та списках виконується через метод `localeCompare` із врахуванням поточної локалі, що забезпечує коректний алфавітний порядок для кириличних та латинських символів.
     
     Система реалізує єдиний підхід до обробки помилок на всіх сторінках. Відповідь HTTP 401 ініціює автоматичний вихід із системи та перенаправлення на сторінку входу. Відповідь HTTP 403 відображає сторінку «Доступ заборонено». Серверні помилки повідомляються користувачеві через toast-сповіщення тривалістю три секунди.
     
     Усі форми містять інлайн-валідацію з відображенням повідомлень про помилки безпосередньо під полями. Операції видалення потребують підтвердження через діалогове вікно. Стани завантаження відображаються через skeleton-елементи для таблиць і карток, або через spinner для форм і кнопок.
     
     У рамках роботи розроблено чотири UML-діаграми:
     Діаграма прецедентів див. рис. Б.2 описує взаємодію чотирьох акторів системи літній користувач, родич, медичний працівник, адміністратор із прецедентами в межах визначеної системної межі. Показано зв'язки «include» та «extend» між залежними прецедентами.
     
     Діаграма компонентів див. рис. Б.3 вказує на використання вузлів, компонентів із стереотипом «component», надаваних інтерфейсів, необхідних інтерфейсів, портів та збірних конекторів. Діаграма охоплює всі компоненти React SPA у браузерному вузлі та зовнішній REST API у серверному вузлі.
     
     Діаграма діяльності див. рис. 	Б.1 моделює сценарій проходження когнітивної вправи від відкриття сторінки через фільтрацію та вибір вправи до збереження результату через API, з гілками обробки помилок та можливістю повторної спроби.
     
     Діаграма станів див. рис. Б.4 описує сценарій додавання родича від перегляду списку через відкриття форми, валідацію та надсилання запиту до успішного завершення або обробки помилки API з можливістю повторної спроби.

4 ВИСНОВКИ

     У ході лабораторної роботи було розроблено front-end частину системи CareLink із підтримкою окремих інтерфейсів для користувачів та адміністраторів. Для реалізації застосовано React, React Router, Axios та i18next, що дозволило забезпечити маршрутизацію, взаємодію з REST API та підтримку локалізації українською й англійською мовами. У системі реалізовано авторизацію на основі JWT, рольовий доступ, адміністративні функції управління користувачами й даними, а також обробку помилок, валідацію форм і адаптацію інтерфейсу до локалі користувача.
